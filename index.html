01 / Why I built it

Sowing by hand is slow, stooped work.

Small farms need tools sized for their plots, their soil and their budgets.

Every school break, my family returns to Nashik, where my grandparents farm. Each visit I saw the same thing: tiny onion seeds pressed into the soil one at a time, by hand, with fewer and fewer workers available to help. Large planting machinery is built for large farms and priced for them too.

SEEDBOT is my answer for small farms: compact enough to turn in tight plots, tracked so it doesn't sink in monsoon mud, and controlled from a smartphone.

The goal

Take the stooping and the hours out of sowing small seeds like onion.

The approach

A compact tracked rover with an arm-mounted auger, Bluetooth app control and a tow hitch for attachments.

Where it stands

Working prototype, field-tested in Nashik, with a provisional patent filed in India.

02 / How it works

Dig. Sow. Cover.

SEEDBOT drives along the bed and plants seed by seed. The arm positions the auger, the auger opens the soil, and the seed goes in at a controlled depth.

  1. DigA stepper-driven auger on the arm bores a planting hole to the set sowing depth.
  2. SowAn onion seed is placed into the hole.
  3. CoverSoil is closed back over the seed, ready to germinate.
Mobility

Tracks for monsoon mud

Tank tracks spread the rover's weight so it doesn't sink into loose, wet soil. Differential steering lets it pivot in place in small plots.

05 / The maths

Modelling the best sowing depth.

For my IB Math AA HL Internal Assessment, I modelled SEEDBOT to find the sowing depth that maximises germinated onion plants per battery charge.

Germination

A separable differential equation models how the chance of germination changes with sowing depth.

Mechanical error

The auger's actual dig depth is modelled as a normal distribution around the target depth.

Optimisation

Using the quotient rule, I maximised germinated plants per unit of battery used.

Result

When the auger's error is normally distributed, the optimal sowing depth shifts deeper in proportion to the error squared, so a less precise auger costs more battery per seed. Making the auger more precise is the point of the next version.

06 / Firmware

The logic behind the hardware.

Two excerpts from SEEDBOT's ESP32 firmware, written in Arduino C++. Wi-Fi and dashboard credentials are replaced with placeholders.

Drive control over Bluetooth

Kick, then ramp. Each move starts with a 200 ms burst at higher power to break the tracks' static friction, then ramps down to cruising speed.

Turns get more power. Pivoting tracks scrub against the ground, so turns hold a higher speed than straight driving.

Mirrored motor. One motor is mounted mirrored, so its direction pins are inverted in software.

#define CUSTOM_SETTINGS
#define INCLUDE_GAMEPAD_MODULE
#include <DabbleESP32.h>

#define ENA 32
#define IN1 33
#define IN2 27
#define ENB 14
#define IN3 19
#define IN4 23

// --- Tuning values ---
const int kickSpeed   = 220;
const int cruiseSpeed = 170;
const int turnSpeed   = 190;  // turns fight more friction than straight driving — slightly higher
const int kickTime    = 200;
const int rampStep    = 5;

int currentSpeed = 0;
int targetSpeed  = 0;
unsigned long moveStartTime = 0;
int direction = 0; // 1 = fwd, -1 = back, 2 = left, -2 = right, 0 = stopped

void setup() {
  Serial.begin(115200);

  pinMode(ENA, OUTPUT);
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
  pinMode(ENB, OUTPUT);
  pinMode(IN3, OUTPUT);
  pinMode(IN4, OUTPUT);

  applyStop();

  Serial.println("Starting Dabble...");
  Dabble.begin("ESP32_Robot");
  Serial.println("Setup done, waiting for Dabble app connection...");
}

void loop() {
  Dabble.processInput();

  bool up    = GamePad.isUpPressed();
  bool down  = GamePad.isDownPressed();
  bool left  = GamePad.isLeftPressed();
  bool right = GamePad.isRightPressed();

  if (up && direction != 1) {
    startMove(1);
  } else if (down && direction != -1) {
    startMove(-1);
  } else if (left && direction != 2) {
    startMove(2);
  } else if (right && direction != -2) {
    startMove(-2);
  } else if (!up && !down && !left && !right && direction != 0) {
    direction = 0;
    targetSpeed = 0;
    currentSpeed = 0;
    applyStop();
  }

  if (direction != 0) {
    if (millis() - moveStartTime > kickTime) {
      // straight moves cruise slower; turns hold a bit more power
      targetSpeed = (direction == 1 || direction == -1) ? cruiseSpeed : turnSpeed;
    }

    if (currentSpeed < targetSpeed) {
      currentSpeed = min(currentSpeed + rampStep, targetSpeed);
    } else if (currentSpeed > targetSpeed) {
      currentSpeed = max(currentSpeed - rampStep, targetSpeed);
    }

    analogWrite(ENA, currentSpeed);
    analogWrite(ENB, currentSpeed);
  }

  delay(10);
}

void startMove(int dir) {
  direction = dir;
  moveStartTime = millis();
  currentSpeed = kickSpeed;
  targetSpeed = kickSpeed;

  if (dir == 1) {
    // FORWARD (Motor B inverted — mounted mirrored)
    digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
    digitalWrite(IN3, LOW);  digitalWrite(IN4, HIGH);
    Serial.println("Forward");
  } else if (dir == -1) {
    // BACKWARD
    digitalWrite(IN1, LOW);  digitalWrite(IN2, HIGH);
    digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);
    Serial.println("Backward");
  } else if (dir == 2) {
    // TURN LEFT: tracks spin opposite ways — pivot in place
    digitalWrite(IN1, LOW);  digitalWrite(IN2, HIGH);
    digitalWrite(IN3, LOW);  digitalWrite(IN4, HIGH);
    Serial.println("Left");
  } else {
    // TURN RIGHT
    digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
    digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);
    Serial.println("Right");
  }

  analogWrite(ENA, currentSpeed);
  analogWrite(ENB, currentSpeed);
}

void applyStop() {
  analogWrite(ENA, 0);
  analogWrite(ENB, 0);
}
Field sensing and live GPS map

ADC1 only. The soil probe sits on an ADC1 pin because the ESP32's ADC2 stops working while Wi-Fi is on.

No false positions. GPS data is parsed every loop so the buffer never overflows, and coordinates are only sent once there is a real fix.

Live map. A small web server on the ESP32 shows the rover's position on a map to any browser on the same network.

#define BLYNK_TEMPLATE_ID "YOUR_VALUE_HERE"
#define BLYNK_TEMPLATE_NAME "YOUR_VALUE_HERE"
#define BLYNK_AUTH_TOKEN "YOUR_VALUE_HERE"

#define BLYNK_PRINT Serial

#include <WiFi.h>
#include <BlynkSimpleEsp32.h>
#include <DHT.h>
#include <TinyGPS++.h>   // parses the raw NMEA text the GPS module spits out
#include <WebServer.h>   // tiny HTTP server built into the ESP32 core

// --- DHT11 ---
#define DHTPIN 4
#define DHTTYPE DHT11
DHT dht(DHTPIN, DHTTYPE);

// --- HC-SR04 ---
#define TRIG_PIN 5
#define ECHO_PIN 18

// --- HW-080 soil moisture probe on HW-103 comparator module ---
// AO (analog out) -> GPIO34. Must be an ADC1 pin (32-39); ADC2 breaks with WiFi.
#define SOIL_AO_PIN 34
#define SOIL_DRY_RAW 4095   // ADC reading in dry air / dry soil (calibrate)
#define SOIL_WET_RAW 1500   // ADC reading fully submerged in water (calibrate)

// --- GY-GPSV3-NEO (u-blox NEO-7M) GPS module ---
// The module talks over a serial (UART) connection at 9600 baud.
// We use the ESP32's second hardware UART, "Serial2", so the main USB
// Serial (used for the Serial Monitor) stays free.
// Wiring:  GPS TX -> GPIO26 (ESP32 RX)   |   GPS RX -> GPIO2 (ESP32 TX)
#define GPS_RX_PIN 26
#define GPS_TX_PIN 2
#define GPS_BAUD   9600 // NEO-7M default baud rate

TinyGPSPlus gps;        // the parser object that decodes the GPS sentences

// Latest decoded GPS values. We keep them in global variables so both the
// Blynk sender and the web page can read the most recent fix.
double gpsLat  = 0.0;
double gpsLon  = 0.0;
int    gpsSats = 0;
bool   gpsHasFix = false;   // true once the module reports a valid position

// --- Local web server (listens on port 80, the default HTTP port) ---
WebServer server(80);

char ssid[] = "YOUR_VALUE_HERE";
char pass[] = "YOUR_VALUE_HERE";

BlynkTimer timer;

// --- Pause control ---
bool paused = false;  // when true, sensor reading/sending is paused

void checkPauseKey() {
  while (Serial.available() > 0) {
    char c = Serial.read();
    Serial.print("RX byte: ");   // DEBUG: shows every char received
    Serial.println((int)c);
    if (c == 'p' || c == 'P') {
      paused = !paused;
      Serial.println(paused ? "Paused" : "Running");
    }
  }
}

// Feed every byte the GPS module has sent into the TinyGPS++ parser.
// This must be called often (every loop) so we don't lose incoming data.
// When the parser has a valid position, we copy it into our globals.
void feedGPS() {
  while (Serial2.available() > 0) {
    gps.encode(Serial2.read());   // hand one character at a time to the parser
  }

  // location.isValid() is true once the module has a real fix (needs sky view).
  if (gps.location.isValid()) {
    gpsLat = gps.location.lat();
    gpsLon = gps.location.lng();
    gpsHasFix = true;
  }

  // Satellite count is reported separately from the position.
  if (gps.satellites.isValid()) {
    gpsSats = gps.satellites.value();
  }
}

// Builds and sends the single HTML page served at "/".
// Shows the current lat/lon as text plus an embedded Google Map.
void handleRoot() {
  String html = "<!DOCTYPE html><html><head>";
  html += "<meta charset='utf-8'>";
  // Tells the browser to reload the whole page every 5 seconds.
  html += "<meta http-equiv='refresh' content='5'>";
  html += "<title>ESP32 GPS</title></head><body>";
  html += "<h1>ESP32 GPS Location</h1>";

  if (gpsHasFix) {
    // String(value, 6) prints the number with 6 decimal places (~0.1 m precision).
    html += "<p><b>Latitude:</b> "  + String(gpsLat, 6) + "</p>";
    html += "<p><b>Longitude:</b> " + String(gpsLon, 6) + "</p>";
    html += "<p><b>Satellites:</b> " + String(gpsSats) + "</p>";

    // No-API-key Google Maps embed: maps.google.com/maps?q=LAT,LON&output=embed
    html += "<iframe width='600' height='450' frameborder='0' style='border:0' ";
    html += "src='https://maps.google.com/maps?q=";
    html += String(gpsLat, 6) + "," + String(gpsLon, 6);
    html += "&output=embed'></iframe>";
  } else {
    html += "<p>Waiting for GPS fix... (move the module near a window or outdoors)</p>";
  }

  html += "</body></html>";
  server.send(200, "text/html", html);   // 200 = HTTP "OK"
}

int readSoilMoisturePct() {
  int raw = analogRead(SOIL_AO_PIN);
  // Dry -> high raw, Wet -> low raw. Map to 0-100% and clamp.
  int pct = map(raw, SOIL_DRY_RAW, SOIL_WET_RAW, 0, 100);
  return constrain(pct, 0, 100);
}

long readDistanceCM() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  long duration = pulseIn(ECHO_PIN, HIGH, 30000); // 30ms timeout
  if (duration == 0) return -1; // no echo received
  return duration * 0.034 / 2;  // convert to cm
}

void sendSensorData() {
  if (paused) return;  // skip while paused

  float h = dht.readHumidity();
  float t = dht.readTemperature();
  long distance = readDistanceCM();
  int soil = readSoilMoisturePct();

  if (isnan(h) || isnan(t)) {
    Serial.println("Failed to read from DHT sensor!");
  } else {
    Blynk.virtualWrite(V0, t);
    Blynk.virtualWrite(V1, h);
  }

  if (distance >= 0) {
    Blynk.virtualWrite(V2, distance);
  }

  Blynk.virtualWrite(V3, soil);

  // Only push GPS coordinates once we actually have a fix, so we don't
  // send 0,0 (a real point in the ocean off Africa) before the module locks on.
  if (gpsHasFix) {
    Blynk.virtualWrite(V4, gpsLat);   // V4 = Latitude  (Double datastream)
    Blynk.virtualWrite(V5, gpsLon);   // V5 = Longitude (Double datastream)
  }

  Serial.printf("Temp: %.1fC  Humidity: %.1f%%  Distance: %ldcm  Soil: %d%%  GPS: %.6f,%.6f sats:%d\n",
                t, h, distance, soil, gpsLat, gpsLon, gpsSats);
}

void setup() {
  Serial.begin(115200);
  Serial.println("\nBooting... send 'p' to pause/resume");
  dht.begin();

  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);

  // Start the GPS on Serial2. The extra arguments set the data format (8N1)
  // and which pins to use for RX and TX.
  Serial2.begin(GPS_BAUD, SERIAL_8N1, GPS_RX_PIN, GPS_TX_PIN);
  Serial.println("GPS serial started on Serial2 (RX=26, TX=2)");

  // Connect WiFi + Blynk. This blocks until WiFi is connected, so after this
  // line WiFi.localIP() is valid and we can start the web server.
  Blynk.begin(BLYNK_AUTH_TOKEN, ssid, pass);

  // Register the "/" page and start listening for browsers.
  server.on("/", handleRoot);
  server.begin();
  Serial.print("Web server started. Open http://");
  Serial.print(WiFi.localIP());   // type this IP into a browser on the same WiFi
  Serial.println("/ in your browser");

  timer.setInterval(2000L, sendSensorData);
}

void loop() {
  checkPauseKey();

  // Keep reading GPS and serving the web page even while "paused".
  // Pausing only stops sending sensor data to Blynk; the GPS parser must run
  // constantly so its serial buffer doesn't overflow, and the web page should
  // stay reachable.
  feedGPS();
  server.handleClient();   // responds to any browser request that came in

  if (!paused) {
    Blynk.run();
    timer.run();
  }
}

07 / Next steps

What the prototype taught me.

SEEDBOT works, but turning it into a tool farmers can rely on every day takes engineering I am still learning.

Limits I found

  • Open-loop controlThe ESP32 can't detect motor stall or positional lag when the auger hits dense soil.
  • Flexing linksThe 3D-printed arm links can deflect under load, pulling the auger off target.
  • Torque to the augerGetting enough torque to the auger in hard soil is still a weak point.

What I'll build next

  • Closed-loop controlRotary encoders and PID control on the arm and auger, so the robot knows when it stalls.
  • A stiffer arm and drivetrainStronger links and better torque transfer, designed with proper mechanical analysis.
  • Calibrated sensingCalibrated soil and pH readings, and depth logged on every run to check the IA model in the field.
